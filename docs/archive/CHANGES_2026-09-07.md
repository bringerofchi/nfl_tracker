## 1. `stat_name` integrity gap (db/repository.py, ingestion/pipeline.py)

**Problem:** `validate_stat_value()` only checked non-negativity for a known
subset of stat names — it never checked whether `stat_name` was a real,
recognized raw-stat category at all. A real Athletic Fantasy Concierge
screenshot exposed this: a bare `fantasy_points` total (21.4), high
confidence, exact player identity match, auto-accepted and wrote directly
into the trusted `projections` table — silently violating "raw stats only,
fantasy points always derived, never stored."

**Fix:** `validate_stat_value(conn, stat_name, value)` now also checks
`stat_name` against `stat_definitions` (same source of truth
`ingest_collector_batch._malformed_reason` already used for the
collector-batch path). Signature changed to take `conn`; 4 call sites
updated (`db/repository.py` internal call sites in `add_statistic` /
`add_projection`; `ingestion/pipeline.py` in `_route_field` and
`accept_proposed_observation`) so both the auto-accept path AND the manual
review-accept path are covered.

**Tests added** (`tests/test_ingestion_pipeline.py`):
- `test_unrecognized_stat_name_never_auto_accepts_even_at_high_confidence`
- `test_recognized_stat_name_still_auto_accepts_after_the_fix`

## 2. Weekly accuracy view silently defaulted to source_name="User" (fantasy/service.py, app.py, templates/player_detail.html)

**Problem:** `player_weekly_view`/`player_trend`/`player_accuracy_summary`
already accepted a `source_name` parameter and were individually correct
per source. But the `/players/<id>` Flask route called all three with no
`source_name` argument at all, silently defaulting to `"User"` every time —
so ESPN's and Yahoo's weekly projection accuracy never appeared on that
page, even with real ESPN/Yahoo weekly projections in the database.

**Fix:** Added `get_weekly_projection_sources()` and
`player_weekly_comparison_by_source()` to `fantasy/service.py`, mirroring
the same "never merge sources" pattern already used by
`player_season_projection_comparison` for scope='season'. Updated the
`/players/<id>` route to use it, and rewrote `templates/player_detail.html`
to render one Accuracy Summary / Weekly View / Trend block per source
instead of one hardcoded block.

**Tests added** (`tests/test_fantasy_service.py`):
- `test_weekly_accuracy_by_source_never_merges_espn_and_yahoo`

**Also manually smoke-tested** (not a checked-in test, just verification
done during this session): a real Flask test-client request to
`/players/<id>` with real ESPN + Yahoo weekly projections and one real
actual seeded — confirmed HTTP 200 and both source names present in the
rendered HTML.
